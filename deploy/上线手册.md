# 阿里云 ECS 上线手册

适用：Ubuntu 22.04 / 2 核 2G 或 4G / 中国香港地域 / 单机部署 Next.js + NestJS + PostgreSQL。

> 全部命令在服务器上执行，默认代码目录 `/var/www/wem`。

---

## 0. 领取实例后先做两件事

1. **安全组放行**：入方向只开 `22`（SSH）、`80`（HTTP）、`443`（HTTPS）。数据库 `5432` **不要**对外。
2. **别装宝塔**：2G 内存机器上宝塔常驻进程会吃掉 300MB+，下面脚本直接用 Nginx + PM2。

---

## 1. 登录并拉代码

```bash
ssh root@<公网IP>

mkdir -p /var/www && cd /var/www
git clone https://github.com/HYH127/web.git wem
cd wem
```

私有仓库需要凭据时，用带 token 的地址：

```bash
git clone https://<USERNAME>:<PAT>@github.com/HYH127/web.git wem
```

---

## 2. 一键装运行时

```bash
sudo bash deploy/bootstrap.sh
```

脚本会：加 2G swap → 装 Node 22 / pnpm 10 / PM2 / Nginx / PostgreSQL 16 → 建库建账号 → 开防火墙。
**结束时会打印 `DATABASE_URL`，务必抄下来**（密码是随机生成的）。

想自己指定数据库密码：

```bash
sudo APP_DB_PASS='你的强密码' bash deploy/bootstrap.sh
```

---

## 3. 写环境变量

### 3.1 前端 `apps/web/.env.production`

```bash
cp apps/web/.env.production.example apps/web/.env.production
nano apps/web/.env.production
```

```ini
NEXT_PUBLIC_API_BASE_URL=https://你的域名.com/api
API_INTERNAL_URL=http://127.0.0.1:4000/api
```

> `NEXT_PUBLIC_*` 是**构建期**注入：改完必须重新 `build` 才生效，只重启进程没用。
> `API_INTERNAL_URL` 让 Next 内部走本机 4000，避免"域名 → Nginx → Next → 域名"的环路。

### 3.2 后端 `apps/api/.env`

```bash
cp apps/api/.env.example apps/api/.env
nano apps/api/.env
```

```ini
DATABASE_URL="postgresql://wem:上一步的密码@127.0.0.1:5432/wem?schema=public"
PORT=4000
NODE_ENV=production
CORS_ORIGIN=https://你的域名.com
JWT_SECRET=<openssl rand -base64 48 的输出>
JWT_EXPIRES_IN=7d
ADMIN_KEY=<另一串随机字符，至少 12 位>
TRUST_PROXY=true
```

生成密钥：

```bash
openssl rand -base64 48
```

## 4. 装依赖 + 建表

```bash
corepack enable && pnpm install --frozen-lockfile
pnpm --filter @wem/api prisma:generate
cd apps/api && pnpm prisma migrate deploy && cd ../..
```

> **不要在生产跑 `prisma:seed`**：种子数据里是演示用的弱密码管理员账号。
> 确实需要初始数据时，先改 `prisma/seed.ts` 里的密码再执行 `pnpm --filter @wem/api prisma:seed`。

---

## 5. 构建

```bash
pnpm --filter @wem/web build
pnpm --filter @wem/api build
```

2G 内存机型若在 Next 构建阶段被 `Killed`，确认 swap 已生效并加大 Node 堆：

```bash
free -h                      # 看 Swap 是否是 2.0Gi
NODE_OPTIONS=--max-old-space-size=1536 pnpm --filter @wem/web build
```

仍然失败时，退路是**在本地 Windows 上 build 完再上传**：

```bash
# 本地执行
tar -czf web-build.tgz apps/web/.next apps/api/dist
# 服务器执行
tar -xzf web-build.tgz
```

## 6. 启动进程

```bash
pm2 start deploy/ecosystem.config.cjs
pm2 save
pm2 startup            # 按提示复制粘贴它输出的那行命令，实现开机自启
pm2 ls
pm2 logs wem-web --lines 30
```

此时本机应可直接访问：

```bash
curl -I http://127.0.0.1:3000          # 200
curl -s http://127.0.0.1:4000/api/health   # 视后端是否实现 health 路由
```

## 7. 配 Nginx 与 HTTPS

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/wem
sudo sed -i 's/your-domain.com/stargalaxytech.xyz/g' /etc/nginx/sites-available/wem
sudo ln -sf /etc/nginx/sites-available/wem /etc/nginx/sites-enabled/wem
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

域名解析到公网 IP 并生效后，签证书（自动改写配置并加 443 段）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d stargalaxytech.xyz -d www.stargalaxytech.xyz --redirect
```

## 9. 日常更新

```bash
cd /var/www/wem
git pull
pnpm install --frozen-lockfile
pnpm --filter @wem/web build && pnpm --filter @wem/api build
pnpm --filter @wem/api prisma:generate   # 若 schema 有变更再跑 prisma migrate deploy
pm2 reload deploy/ecosystem.config.cjs
```

只改前端文案时，最后一行可以换成 `pm2 reload wem-web`。

### 9.1 只同步首页地图数据（不重置其它表）

```bash
cd /var/www/wem
pnpm --filter @wem/api trade:sync    # 重写 TradeStat + ShipmentRoute
pm2 reload wem-web                    # 首页有 60s ISR 缓存，重启可立刻看到
```

地图数据源在 `apps/api/prisma/trade-data.ts`。新增国家时**必须同时**在
`apps/web/src/lib/world.ts` 的 `ISO_ALPHA2_TO_NUM` 里补 ISO 数字码（如 `RU: "643"`），
否则该国只会有光点、不会被染色——底图路径是按数字码取的。

### 9.2 新建 / 重置管理员

```bash
cd /var/www/wem
ADMIN_EMAIL='you@example.com' ADMIN_PASSWORD='至少8位' ADMIN_NAME='站点管理员' \
  pnpm --filter @wem/api admin:create
```

不导演示数据、不动其它表；账号不存在就新建，已存在则覆盖密码并提升为 ADMIN，
同时 `tokenVersion + 1` 让旧会话立即失效。

### 9.3 只灌工厂实例数据（不重置其它表）

首次上线时 `migrate deploy` 只建表不灌数据，`/factory` 会是空的。

```bash
cd /var/www/wem
pnpm --filter @wem/api factory:seed   # 按 slug 幂等 upsert，可反复执行
```

数据源是 `apps/api/prisma/factory-data.ts`（与 `prisma/seed.ts` 共用同一份）。
`prisma db seed` 会 **清空全库**（含管理员账号），生产环境不要用。

## 10. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 502 Bad Gateway | Next 进程没起来：`pm2 logs wem-web`；或端口不是 3000 |
| 页面能开但接口全 500 | `NEXT_PUBLIC_API_BASE_URL` 没在 build 前设置，包里还是 `localhost:4000`。改 `.env.production` 后**重新 build** |
| 上传的图片 404 | Nginx 的 `/uploads/` 必须转 `127.0.0.1:4000`（不是 3000），见 `deploy/nginx.conf` |
| `/api/xxx` 返回 404 | Nginx 缺 `location /api/` 段；站内代码走 `/backend/*`，`/api/*` 是给外部联调的另一条通道 |
| 首页地图空白、没有小人 | `TradeStat` 表为空：跑 `pnpm --filter @wem/api trade:sync` |
| 工厂实例页面空白 | `FactoryPost` 表为空：跑 `pnpm --filter @wem/api factory:seed` |
| 注册收不到验证码 | 生产环境 `deliverCode` 只写日志，需接 SMTP（遗留项） |
| 构建被 Killed | 内存不足，见第 5 节 swap / 本地构建上传 |
| 登录后立刻掉线 | Cookie 是 `secure` 的，必须走 HTTPS；纯 HTTP 访问域名会丢会话 |
| 内地 IP 打不开 80/443 | 地域是内地且未备案，试用机不支持备案 → 换香港地域 |

## 11. 安全基线

上线时已完成的三层加固，换了机器或重装系统时按此表逐项复原。

| 层 | 措施 | 在哪里 |
|---|---|---|
| 应用 | API 只监听 `127.0.0.1:4000`（`HOST` 可覆盖），外部无法直连绕过 HTTPS | `apps/api/src/main.ts` |
| 应用 | 上传先判魔术字节再落盘，扩展名由真实类型决定，不信客户端 MIME | `apps/api/src/factory/factory.controller.ts` |
| 应用 | 生产环境不挂载 Swagger | `apps/api/src/main.ts` |
| 应用 | 登录/注册/询盘限流 + 失败锁定 + 验证码尝试次数 + 蜜罐 | `app.module.ts`、`auth.controller.ts` |
| 应用 | 口令 scrypt 哈希、`tokenVersion` 全端下线、会话 HttpOnly + Secure | `auth.service.ts` |
| 页面 | CSP（禁外部域 / 禁 eval / 禁 object / frame-ancestors none）、HSTS 一年、nosniff、X-Frame-Options、Permissions-Policy | `apps/web/next.config.ts` |
| 反代 | `server_tokens off`、拦截 `/api/docs` 与点文件、上传目录只读 | `/etc/nginx/nginx.conf`、`deploy/nginx.conf` |
| 主机 | ufw 仅放行 22/80/443，默认拒绝入站 | `ufw enable` |
| 主机 | fail2ban 守护 SSH：10 分钟 5 次失败封 1 小时，递增至 24 小时 | `/etc/fail2ban/jail.local` |
| 主机 | 自动安全更新 | `unattended-upgrades`（Ubuntu 默认已启用） |

### 11.1 验证

```bash
# 1. 版本号不再暴露（应为 Server: nginx，不带版本）
curl -sI https://stargalaxytech.xyz/ | grep -i '^server'

# 2. 页面安全头齐全
curl -sI https://stargalaxytech.xyz/ | grep -iE 'content-security-policy|strict-transport-security|x-frame-options|x-content-type-options'

# 3. 接口文档已拦
curl -s -o /dev/null -w '%{http_code}\n' https://stargalaxytech.xyz/api/docs   # 期望 404

# 4. 点文件不可读
curl -s -o /dev/null -w '%{http_code}\n' https://stargalaxytech.xyz/.env       # 期望 404

# 5. 4000 端口对外不可达（绑定回环 + ufw 双保险）
curl -m 5 -o /dev/null -w '%{http_code}\n' http://47.76.118.92:4000/api/health   # 期望 000

# 6. 主机防火墙与入侵防护
ufw status verbose | head -8
fail2ban-client status sshd | tail -4
```

### 11.2 启用 ufw 的顺序（重要）

**先放行 22 再 enable**，否则会把自己关在门外：

```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
ufw default deny incoming
ufw default allow outgoing
ufw --force enable
```

阿里云安全组是另一层，需要在控制台单独放行 80/443；两层都不要开 3000/4000。

### 11.3 已知取舍

- **CSP 带 `'unsafe-inline'`**：Next App Router 会内联流式数据脚本，去掉它整页白屏。
  当前策略仍能挡住外部域脚本、`eval` 与 XSS 数据外带，但挡不住内联注入。
  要更严需改用 middleware 下发 nonce，改动面较大。
- **没有 WAF / 没有 CDN 层防护**：目前靠应用层限流。若遭遇大规模 CC，
  先在阿里云侧开 DDoS 基础防护或接 CDN。
- **上传仍存本机磁盘**：目录里只会有通过魔术字节校验的图片，但实例重建会丢，
  且没有病毒扫描。换 OSS 时记得同步加内容审核。
