# 阿里云 ECS 上线手册

适用：Ubuntu 22.04 / 2 核 2G 或 4G / 中国香港地域 / 单机部署 Next.js + NestJS + PostgreSQL。

> 全部命令在服务器上执行，默认代码目录 `/var/www/wem`。

---

## 0. 领取实例后先做两件事

1. **安全组放行**：入方向只开 `22`（SSH）、`80`（HTTP）、`443`（HTTPS）。数据库 `5432` **不要**对外。
2. **别装宝塔**：2G 内存机器上宝塔常驻进程会吃掉 300MB+，下面脚本直接用 Nginx + PM2。

---

## 1. 登录并拉代码

```bash
ssh root@<公网IP>

mkdir -p /var/www && cd /var/www
git clone https://github.com/HYH127/web.git wem
cd wem
```

私有仓库需要凭据时，用带 token 的地址：

```bash
git clone https://<USERNAME>:<PAT>@github.com/HYH127/web.git wem
```

---

## 2. 一键装运行时

```bash
sudo bash deploy/bootstrap.sh
```

脚本会：加 2G swap → 装 Node 22 / pnpm 10 / PM2 / Nginx / PostgreSQL 16 → 建库建账号 → 开防火墙。
**结束时会打印 `DATABASE_URL`，务必抄下来**（密码是随机生成的）。

想自己指定数据库密码：

```bash
sudo APP_DB_PASS='你的强密码' bash deploy/bootstrap.sh
```

---

## 3. 写环境变量

### 3.1 前端 `apps/web/.env.production`

```bash
cp apps/web/.env.production.example apps/web/.env.production
nano apps/web/.env.production
```

```ini
NEXT_PUBLIC_API_BASE_URL=https://你的域名.com/api
API_INTERNAL_URL=http://127.0.0.1:4000/api
```

> `NEXT_PUBLIC_*` 是**构建期**注入：改完必须重新 `build` 才生效，只重启进程没用。
> `API_INTERNAL_URL` 让 Next 内部走本机 4000，避免"域名 → Nginx → Next → 域名"的环路。

### 3.2 后端 `apps/api/.env`

```bash
cp apps/api/.env.example apps/api/.env
nano apps/api/.env
```

```ini
DATABASE_URL="postgresql://wem:上一步的密码@127.0.0.1:5432/wem?schema=public"
PORT=4000
NODE_ENV=production
CORS_ORIGIN=https://你的域名.com
JWT_SECRET=<openssl rand -base64 48 的输出>
JWT_EXPIRES_IN=7d
ADMIN_KEY=<另一串随机字符，至少 12 位>
TRUST_PROXY=true
```

生成密钥：

```bash
openssl rand -base64 48
```

## 4. 装依赖 + 建表

```bash
corepack enable && pnpm install --frozen-lockfile
pnpm --filter @wem/api prisma:generate
cd apps/api && pnpm prisma migrate deploy && cd ../..
```

> **不要在生产跑 `prisma:seed`**：种子数据里是演示用的弱密码管理员账号。
> 确实需要初始数据时，先改 `prisma/seed.ts` 里的密码再执行 `pnpm --filter @wem/api prisma:seed`。

---

## 5. 构建

```bash
pnpm --filter @wem/web build
pnpm --filter @wem/api build
```

2G 内存机型若在 Next 构建阶段被 `Killed`，确认 swap 已生效并加大 Node 堆：

```bash
free -h                      # 看 Swap 是否是 2.0Gi
NODE_OPTIONS=--max-old-space-size=1536 pnpm --filter @wem/web build
```

仍然失败时，退路是**在本地 Windows 上 build 完再上传**：

```bash
# 本地执行
tar -czf web-build.tgz apps/web/.next apps/api/dist
# 服务器执行
tar -xzf web-build.tgz
```

---

## 6. 启动进程

```bash
pm2 start deploy/ecosystem.config.cjs
pm2 save
pm2 startup            # 按提示复制粘贴它输出的那行命令，实现开机自启
pm2 ls
pm2 logs wem-web --lines 30
```

此时本机应可直接访问：

```bash
curl -I http://127.0.0.1:3000          # 200
curl -s http://127.0.0.1:4000/api/health   # 视后端是否实现 health 路由
```

---

## 7. 配 Nginx 与 HTTPS

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/wem
sudo nano /etc/nginx/sites-available/wem     # 把 your-domain.com 换成真实域名
sudo ln -sf /etc/nginx/sites-available/wem /etc/nginx/sites-enabled/wem
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

域名解析到公网 IP 并生效后，签证书（自动改写配置并加 443 段）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名.com -d www.你的域名.com
```

---

## 8. 验收清单

```bash
curl -I https://你的域名.com/                 # 200，且响应头有 strict-transport-security
curl -I https://你的域名.com/_next/static/... # 200，cache-control: immutable
curl -s https://你的域名.com/api/factory/posts # 返回 {"success":true,...}
```

页面逐项点一遍：首页 `/` → 产品 `/shop` → 案例 `/factory` → 联系表单提交 → 注册/登录 → 后台 `/factory/write` 传图。

---

## 9. 日常更新

```bash
cd /var/www/wem
git pull
pnpm install --frozen-lockfile
pnpm --filter @wem/web build && pnpm --filter @wem/api build
pnpm --filter @wem/api prisma:generate   # 若 schema 有变更再跑 prisma migrate deploy
pm2 reload deploy/ecosystem.config.cjs
```

只改前端文案时，最后一行可以换成 `pm2 reload wem-web`。

## 10. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 502 Bad Gateway | Next 进程没起来：`pm2 logs wem-web`；或端口不是 3000 |
| 页面能开但接口全 500 | `NEXT_PUBLIC_API_BASE_URL` 没在 build 前设置，包里还是 `localhost:4000`。改 `.env.production` 后**重新 build** |
| 上传的图片 404 | Nginx 的 `/uploads/` 必须转 `127.0.0.1:4000`（不是 3000），见 `deploy/nginx.conf` |
| 注册收不到验证码 | 生产环境 `deliverCode` 只写日志，需接 SMTP（遗留项） |
| 构建被 Killed | 内存不足，见第 5 节 swap / 本地构建上传 |
| 登录后立刻掉线 | Cookie 是 `secure` 的，必须走 HTTPS；纯 HTTP 访问域名会丢会话 |
| 内地 IP 打不开 80/443 | 地域是内地且未备案，试用机不支持备案 → 换香港地域 |

## 11. 已知遗留

- 生产环境注册验证码只 `logger.log`，没有真实发信通道。
- 演示管理员账号密码偏弱，上线前务必改 `prisma/seed.ts` 或干脆不 seed。
- 图片存本机磁盘，实例重建会丢；后续建议换 OSS + CDN。
