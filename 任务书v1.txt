外贸独立站 MVP Vibecoding 任务书
一、项目目标与 MVP 边界
1.1 项目目标
构建一个面向 B2B 外贸客户的独立站 MVP，体现：
• 全球化交易可视化与物流动效；
• B2B 合作案例展示与信任背书；
• 常规商城、注册登录、购物车、订单占位能力；
• 社交媒体入口；
• 大胆创新但协调一致的高级视觉风格。
1.2 MVP 必须包含
 
 
模块
MVP 要求
首页
非全屏大图首屏、透明前景文案层、全球地图可视化占位、地区亮度占位、缓慢呼吸光效、小人抱箱从浙江出发到高亮国家并空手返回
B2B 案例
案例列表页、案例详情页、按大洲筛选、占位案例数据、可点击跳转
社媒跳转
YouTube / TikTok / Facebook / Instagram 入口，链接暂跳首页
商城骨架
商品列表、商品详情、购物车占位、结算占位
账户
注册、登录、用户中心骨架，前后端分离
后端
API 契约、数据库模型、占位数据、认证接口
视觉
设计 Token、响应式、动效规范、可访问性基础
部署
前后端可分别启动和部署的 MVP 框架
1.3 MVP 明确不做
• 不填真实案例长文、真实商品、真实价格、真实社媒链接；
• 不接真实支付、物流、发票、ERP；
• 不做完整后台 CMS，仅保留内容管理扩展位；
• 不做复杂订单履约和售后；
• 不做高精度世界地图和真实交易大数据；
• 不做多语言完整翻译，仅预留国际化结构。

2.2 架构原则
• 前后端分离，前端不直连数据库；
• 所有内容先用 Mock API 或 Seed 占位数据；
• API 契约先冻结，再实现；
• 组件与页面分离，地图动效独立成可替换模块；
• 所有真实内容入口用配置或数据库字段预留；
• 动效支持 prefers-reduced-motion 降级；
• 移动端简化地图光效和小人动画，保证性能。

4.2 API 契约要求
• 先输出 OpenAPI/Swagger 或接口文档；
• 案例列表支持 continent 筛选；
• 地图接口返回地区交易次数与亮度等级；
• 首页接口返回首屏文案、社媒配置、地图占位数据；
• 所有接口返回统一错误结构；
• MVP 使用 Seed 数据，不接真实业务数据。
 
五、视觉与动效规范
5.1 视觉方向
关键词：深海暗色基底、冷光青/冰蓝主光、香槟金点缀、玻璃拟态局部、编辑式大字号排版、克制留白、专业高级感。
要求：
• 首页大图不是全屏，占首屏约 65%–80%，前景透明层放标题、副标题、CTA；
• 地图低细节、低饱和轮廓，交易亮度用光晕表达；
• 小人风格简洁几何/剪影，不要过度卡通；
• 案例页偏 B2B 信任感，数据卡片、客户 Logo 占位、时间线；
• 全站统一设计 Token：颜色、字号、间距、圆角、阴影、光晕、动效时长。
5.2 地图灯光与小人动效规范
• 地图：低精度世界地图，国家轮廓简化；
• 亮度：按交易次数分级映射，避免极值过曝；
• 呼吸：周期约 5–7 秒，缓入缓出，不做快速闪烁；
• 小人：从中国浙江省出发，跑到高亮国家，停留后空手返回；
• 路线调度：MVP 同时最多 1–2 条路线，避免杂乱；
• 移动端：降低光晕层数、减少同屏路线、可关闭呼吸；
• 性能：动画层与地图层分离，支持降级静态高亮。
 
六、Vibecoding 分步任务
执行原则：每个 Step 只做当前范围；所有内容用占位数据；不得提前填充真实案例、商品、社媒链接；每步完成后提交评审。
Step 0：需求冻结与设计系统
任务
• 确认页面清单、路由、MVP 边界；
• 输出设计 Token 初稿：色板、字体层级、间距、圆角、光效、动效时长；
• 输出组件清单：导航、页脚、按钮、卡片、筛选器、地图容器、案例卡片、商品卡片；
• 输出 API 契约草案和数据库模型草案。
产出
• 设计系统说明；
• 路由表；
• 组件清单；
• API/数据模型草案。
验收
• 你确认视觉方向和 MVP 范围后进入下一步。
 
Step 1：项目框架与前后端脚手架
任务
• 建立前端、后端、数据库基础工程；
• 配置 TypeScript、环境变量、代码规范、基础 CI；
• 前端建立全局布局、导航、页脚、社媒图标占位；
• 后端建立健康检查、统一响应结构、Swagger/接口文档入口；
• 数据库建立 Prisma schema 初稿和 Seed 占位数据。
产出
• 前后端可分别启动；
• 空首页可访问；
• 健康检查和接口文档可访问；
• 占位 Seed 数据可入库。
验收
• 前后端分离结构清晰；
• 无真实业务内容；
• 路由和配置可扩展。
 
Step 2：前端路由与页面骨架
任务
• 建立首页、案例列表、案例详情、商城列表、商品详情、购物车、结算、登录、注册、用户中心骨架；
• 所有页面使用统一布局和占位卡片；
• 社媒入口统一跳转首页；
• 建立 404、加载态、空状态、错误态。
产出
• 全站可点击跳转的 MVP 骨架；
• 响应式布局基础。
验收
• 所有路由可访问；
• 页面之间跳转正常；
• 内容均为占位。
 
Step 3：首页首屏与地图静态可视化
任务
• 实现非全屏首页大图与透明前景文案层；
• 嵌入低精度世界地图；
• 用占位交易数据渲染国家亮度层级；
• 完成地图光晕、呼吸效果基础版；
• 增加小人抱箱静态/基础路径动画骨架；
• 移动端降级方案。
产出
• 首页可评审视觉版；
• 地图亮度和呼吸可调参；
• 小人路线占位动画可运行。
验收
• 呼吸不快速闪烁；
• 地图细节低但灯光好看；
• 前景文字清晰可读；
• 移动端不卡顿、不溢出。
 
Step 4：案例模块 B2B 信任展示
任务
• 案例列表页：卡片、大洲筛选、空状态；
• 案例详情页：客户背景、合作记录、成果指标占位；
• 后端提供案例列表/详情/筛选接口；
• 前端接 Mock/Seed 数据。
产出
• /cases 和 /cases/[slug] 可完整走通；
• 按大洲筛选可用。
验收
• 筛选后列表正确；
• 详情可返回列表；
• 内容为占位但结构完整。
 
Step 5：商城与账户骨架
任务
• 商品列表/详情、购物车、结算、登录、注册、用户中心骨架；
• 注册登录接后端 JWT；
• 购物车先用本地或占位接口；
• 支付只做按钮和状态占位。
产出
• 注册登录联调通过；
• 商品到购物车流程可点击；
• 订单和支付为占位。
验收
• 不接真实支付；
• 用户数据可入库；
• 页面状态完整。
 
Step 6：后端数据与 API 完善
任务
• 完成认证、商品、案例、地图交易、站点配置接口；
• 统一分页、筛选、错误码；
• Seed 占位数据覆盖所有页面；
• 输出 API 文档。
产出
• 前端可完全基于 API 渲染；
• 地图交易统计和案例筛选有接口支撑。
验收
• 接口契约稳定；
• 前后端无硬编码内容依赖。
 
Step 7：联调、性能与可访问性
任务
• 前后端联调；
• 地图动效性能优化；
• 响应式检查；
• 键盘可访问、对比度、动效降级；
• SEO 基础：标题、描述、OG 占位。
产出
• MVP 可评审版本；
• 性能与可访问性检查清单。
验收
• 桌面与移动端可用；
• 动效不干扰阅读；
• 无严重控制台错误。
 
Step 8：MVP 评审与内容填充准备
任务
• 汇总评审问题；
• 输出内容填充清单：案例、商品、社媒链接、地图真实数据、支付、物流；
• 冻结框架版本。
产出
• MVP 评审版；
• 下一阶段内容填充任务书。
验收
• 你确认框架和视觉方向后，再进入真实内容填充。
 
七、MVP 验收标准
1. 首页大图非全屏，透明前景文字清晰；
2. 全球地图低细节，亮度按占位交易数据变化；
3. 呼吸效果缓慢、克制，无明显闪烁；
4. 小人从浙江出发到高亮国家并空手返回，路线不混乱；
5. 案例列表可按大洲筛选，详情可点入；
6. 社媒入口存在且暂跳首页；
7. 注册登录前后端联通；
8. 商品、购物车、结算、用户中心骨架完整；
9. 所有内容为占位数据；
10. 桌面与移动端布局协调，风格统一高级。

九、需要你确认的事项
1. 品牌主色倾向：冷光青+深海蓝，还是香槟金点缀更强？
2. 首页首屏大图高度：约 70% 首屏是否合适？
3. 小人风格：几何剪影还是轻拟物？
4. 案例筛选是否只按大洲，还是大洲+行业？
5. 商城 MVP 是否先只做展示和购物车占位，不接支付？
6. 是否需要中英双语框架预留？
